What this system does

This project is a low-cost AIoT air-quality monitoring system built around an ESP32 sensor node, an MQTT communication layer, a Flask backend, a local sensor database, and a cloud-hosted CPCB air-quality database.

The monitoring dashboard combines PM2.5 and PM10 from the Vadodara CPCB data source with CO and NH₃ measured by the ESP32 node. Temperature and humidity are also measured locally using DHT11 to provide environmental context.

The dashboard is focused on real-time monitoring, historical analytics, and alerts. AQI forecasting is kept in a separate CPCB prediction dashboard so that monitoring and machine-learning prediction remain clearly separated.

CPCB AQI Categories & Precautions

The dashboard uses six AQI categories from Good to Severe. The table below explains the AQI range, likely health impact, and practical precautions associated with each category.

Category AQI Range Health Impact Practical Precautions
Good 0–50 Minimal impact. Air quality is considered good for normal daily activities. Normal outdoor activities can continue. Outdoor exercise and recreation can continue as usual.
Satisfactory 51–100 Air quality is generally acceptable. Sensitive people may experience minor breathing discomfort. Normal activities can continue for most people. Sensitive people should monitor for breathing discomfort and reduce prolonged or strenuous outdoor exertion if discomfort occurs.
Moderate 101–200 Breathing discomfort may occur in people with lung, asthma, or heart conditions, especially during prolonged exposure. Sensitive groups should consider reducing prolonged or strenuous outdoor activity, take additional breaks, and move indoors if breathing discomfort occurs.
Poor 201–300 Prolonged exposure may cause breathing discomfort, particularly for people with respiratory or heart conditions. Reduce prolonged or strenuous outdoor physical activity. Sensitive groups should minimize outdoor exertion and consider moving strenuous activities indoors.
Very Poor 301–400 Prolonged exposure can cause respiratory illness or significant breathing discomfort. Avoid strenuous outdoor physical activity. Sensitive groups should remain indoors as much as practical and keep outdoor exposure as short as reasonably possible.
Severe 401–500 Air quality may affect healthy people and can seriously affect people with existing respiratory or cardiovascular conditions. Avoid outdoor physical activity where possible. Minimize outdoor exposure, especially for sensitive groups, and move strenuous activities indoors.
Note: AQI ranges follow the CPCB category structure used by the dashboard. Precaution text is general guidance and is not individualized medical advice.

Sensor measurements are published by the ESP32 through the public HiveMQ MQTT broker. The Flask backend subscribes to the MQTT topic and stores sensor readings in the local SQLite database. PM2.5 and PM10 are read from the existing Render PostgreSQL CPCB database.

In the current local deployment, the Flask backend must be running for MQTT sensor messages to be received and stored. The ESP32 itself can operate from an independent power source after the firmware has been uploaded.

How Current AQI is calculated

The Live dashboard uses the latest available values for four pollutants:

Pollutant Source Unit
PM2.5 Vadodara CPCB / Render PostgreSQL µg/m³
PM10 Vadodara CPCB / Render PostgreSQL µg/m³
CO ESP32 MQ-7 mg/m³
NH₃ ESP32 MQ-135 µg/m³

Each pollutant is converted to an AQI sub-index using the project's CPCB breakpoint implementation. The displayed Current AQI is the highest of the four available sub-indices. The pollutant producing that maximum value is shown as the dominant pollutant.

Important: the dashboard's Current AQI is a project real-time four-pollutant indicator. Official CPCB AQI uses prescribed pollutant averaging periods and regulatory monitoring procedures. Therefore this dashboard should not be presented as an official CPCB station AQI.

Separate CPCB AQI prediction system

AQI prediction is handled by a separate Vadodara CPCB prediction dashboard. It uses historical CPCB pollutant data and the trained machine-learning forecasting models rather than mixing the prediction workflow into the portable sensor dashboard.

This separation keeps the system easier to explain: the AIoT dashboard demonstrates monitoring, communication, analytics, and alerts, while the CPCB dashboard demonstrates Vadodara AQI forecasting.

Navigation to the prediction system is provided through CPCB Prediction ↗ in the top menu. It opens the separate Vadodara CPCB prediction dashboard in a new tab.

Location and seminar demonstration

The integrated monitoring setup was designed around Vadodara CPCB PM data together with local ESP32 CO and NH₃ measurements. For a scientifically meaningful combined AQI, the pollutant sources should represent the same monitoring area and time period.

If the ESP32 node is later operated in Myanmar for the seminar, it can still demonstrate live sensing, Wi-Fi, MQTT communication, CO, NH₃, temperature, and humidity. However, Myanmar sensor readings should not be combined with Vadodara CPCB PM2.5/PM10 and presented as one location's AQI.

For the seminar, stored Vadodara monitoring results and the Vadodara CPCB prediction dashboard can be presented as the project results, while the physical ESP32 can be demonstrated separately as the portable IoT node.

Measurement limitations

The MQ-7 and MQ-135 are low-cost semiconductor gas sensors. Their readings can be influenced by calibration, heater conditions, power supply, temperature, humidity, airflow, sensor aging, and cross-sensitivity to other gases.

For this reason, CO and NH₃ values from the node should be presented as low-cost sensor estimates used for the project prototype, not as regulatory-grade measurements.

The project also does not locally measure NO₂, SO₂, O₃, or lead. The monitoring dashboard intentionally focuses on the four pollutants available in the integrated setup: PM2.5, PM10, CO, and NH₃.
